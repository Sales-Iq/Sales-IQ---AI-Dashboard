1. PLATFORM OVERVIEW & EXECUTIVE SUMMARY
================================================================================

1.1 Mission & Vision
--------------------
SalesIQ is an all-in-one, modern, enterprise-grade cloud operating system designed 
specifically for retail businesses, multi-branch wholesale distributors, FMCG stores, 
and electronic merchants. It bridges the critical divide between point-of-sale (POS) 
transactions, real-time inventory management, vendor supply chains, and artificial 
intelligence. 

Unlike legacy ERP software that is clunky, slow, and reactive, SalesIQ transforms raw 
transaction logs into proactive, forward-looking business intelligence. By marrying 
low-latency cloud data persistence with Google's Gemini large language models, SalesIQ 
gives shop owners and corporate executives an automated business analyst that continuously 
monitors stockouts, forecasts seasonal reorders, models revenue growth trajectories, 
and safeguards profit margins.

1.2 Target Business Domains
---------------------------
- Supermarkets, Grocery Stores & Convenience Markets
- Consumer Electronics, Mobile Phone Showrooms & Hardware Retailers
- Fashion Boutiques, Apparel Chains & Footwear Outlets
- Pharmaceutical & Health Care Distribution Counters
- Wholesale Distributors, Stockists & Supply Hubs
- Multi-staff Retail Counters requiring role-segregated POS billing terminals

1.3 Core Value Propositions
---------------------------
- Zero-Lag Realtime Persistence: Synchronized across multiple cash registers and 
  admin monitors in under 50ms via Google Cloud Firestore.
- Autonomous AI Intelligence: Continuous data synthesis powered by a resilient 
  multi-model cascade of Google Gemini models with automatic quota failover.
- Offline-First 3-Tier Caching: Instant page-to-page navigation with zero-millisecond 
  perceived UI latency via RAM maps, sessionStorage, and IndexedDB caching.
- Role-Based Operational Security: Complete privilege isolation ensuring sales staff 
  cannot tamper with product costs, profit margins, sales history, or vendor contacts.
- Lumelle Liquid Glass Aesthetics: Ultra-premium, tactile visual experience featuring 
  chromatic caustics, physical glass refraction, smooth Lenis inertia scrolling, 
  and responsive mobile sheets.
- Global Multi-Currency Support: Real-time live exchange rate synchronization 
  converting base INR values to USD, EUR, GBP, AED, CAD, AUD, and SGD on the fly.

1.4 Technological Stack & Standards
-----------------------------------
- Frontend Architecture: Zero-framework, clean ES6+ Modular JavaScript architecture.
  No complicated npm build steps or webpack bundling required; boots instantly via any 
  standard web server (VS Code Live Server, Firebase Hosting, Nginx, Vercel).
- Visual Layer: Tailwind CSS (Modern Utility Foundation) combined with custom CSS

- Animation & Physics: Lenis Smooth Scrolling Engine, Framer Motion spring physics,

2. SYSTEM ARCHITECTURE & CORE PLATFORM ENGINES
================================================================================

2.1 Multi-Model Google Gemini AI Orchestration Engine (js/gemini-service.js)
----------------------------------------------------------------------------
The AI engine within SalesIQ is built with enterprise resilience to guarantee 100% 
uptime even under strict API rate limits or quota constraints:
- Multi-Model Priority Registry:
  * Primary Intelligence Tier: Gemini 3.8 Flash, Gemini 3.5 Flash, Gemini 3 Flash Preview 
    (High-reasoning models dedicated to strategic forecasting and business insights).
  * High-Throughput / High-Quota Tier (500 RPD): Gemini 2.5 Flash Lite, Gemini 3.1 Flash Lite, 
    Gemini 3.5 Flash Lite (Specialized for high-volume JSON extraction and CSV mapping).
  * Backstop Emergency Tier: Gemini 2.0 Flash, Gemini 1.5 Flash.
  * Audio / Voice Tier: Gemini 3.8 Flash TTS.
- Dynamic Quota Failover: Monitors HTTP 429 and rate-limit responses; automatically switches 
  to the next candidate model in milliseconds without interrupting the user.
- Local Storage Quota Cooldowns: Remembers model cooldown windows (1 hour by default) 
  to prevent redundant failed API calls.
- AI-Powered Spreadsheet Column Mapper: Automatically inspects arbitrary user-uploaded 
  Excel/CSV spreadsheets, analyzes column titles and sample row data, and matches them to 
  the SalesIQ product catalog schema (Name, MRP, Cost Price, Stock, Reorder Level, Category).
- Offline Synonym Engine: Built-in rule-based synonym dictionary that provides instant 
  local column mapping if internet or API keys are unavailable.
- Dynamic Key Management: Allows administrators to input custom Gemini API keys directly 
  from the UI Settings panel with instant local storage override.

2.2 High-Performance 3-Tier Client Caching Architecture (js/idb-cache.js)
-------------------------------------------------------------------------
To eliminate loading spinners and ensure sub-millisecond perceived performance:
- Tier 1 (Memory Map): Active in-memory JS Map providing instantaneous 0ms reads for 
  currently mounted views.
- Tier 2 (Session Storage): Fast multi-kilobyte cache surviving soft refreshes and tab focus.
- Tier 3 (IndexedDB Engine - salesiq_cache_db_v2): High-capacity client-side structured 
  storage capable of persisting 50MB+ of inventory documents, historical transactions, 
  and analytics aggregations across browser sessions.
- Stale-While-Revalidate Sync: Cached data renders on screen instantly (<5ms) while a 
  background Firebase snapshot verifies and seamlessly patches fresh updates.

2.3 Real-Time Firestore Data Layer & Sync System (js/shared.js, js/firebase-config.js)
--------------------------------------------------------------------------------------
- Bi-directional Websocket Listeners: Utilizes Firestore onSnapshot listeners for real-time 
  reactivity across inventory updates, new POS sales, and critical stock notifications.
- Automatic Offline Fallback: If network drops, automatically degrades to one-time cache 
  fetches with non-intrusive toast notifications.
- Transactional Inventory Decrement: POS billing executes transactional updates to prevent 
  overselling and race conditions across multiple simultaneous cash registers.
- Document Hygiene & Scrubbing: Includes deduplication routines (admin/cleanup-duplicates.js) 
  to maintain zero-redundancy across Firestore collections.

2.4 Dynamic Live Simulation & Demo Seeder Engine (js/demo-live-data.js, admin/js/demoSeeder.js)
-----------------------------------------------------------------------------------------------
- Instant Retail Demo Seeder: One-click generation of 20+ realistic retail inventory items 
  across 6 major retail categories (Beverages, Snacks, Electronics, Personal Care, Bakery, Dairy).
- Realtime Live Transaction Simulator: Generates realistic mock sales every 3 to 7 seconds, 
  simulating walk-in customers, varying cart quantities, cash/UPI/card payments, and live stock decrements.
- Strict Data Isolation: Demo sales and demo products are tagged with source='dummy' and 
  isDemo=true, preventing corruption of real production sales records or profit reports.
- UI Control Panel: Floating interactive demo toolbar on the Admin Dashboard allowing administrators 
  to Start, Pause, or Flush simulated traffic on demand.

2.5 Global Multi-Currency & Live Exchange Rate Engine (js/shared.js)
-------------------------------------------------------------------
- Base Currency Architecture: All records are internally preserved in high-precision Indian Rupees (INR ₹) 
  to maintain absolute mathematical consistency across reports.
- Live Forex API Integration: Synchronizes every 6 hours with open.er-api.com to fetch real-world 
  exchange rates for global currencies:
  * USD ($) - US Dollar
  * EUR (€) - Euro
  * GBP (£) - British Pound Sterling
  * AED (AED) - UAE Dirham
  * CAD (CA$) - Canadian Dollar
  * AUD (A$) - Australian Dollar
  * SGD (SG$) - Singapore Dollar
- Dynamic Frontend Transformation: Switching currencies in Settings instantly re-renders all 
  historical sales, stock valuations, revenue graphs, and invoices in the selected foreign currency.
- International Number Formatting: Utilizes the native Intl.NumberFormat standard for authentic 
  local digit grouping (e.g., Lakhs/Crores for en-IN vs Millions for en-US).

2.6 Lumelle Liquid Glass Design System & Micro-Interactions (css/liquid-glass.css, js/liquid-glass.js)
------------------------------------------------------------------------------------------------------
- 1.5px Bevel Rim Knockout Mask: Patented CSS mask-image technique that renders genuine frosted glass 
  rim highlights without heavy multi-layer DOM nesting.
- Chromatic Caustics & Optical Refraction: Background radial glows and specular light streaks simulate 
  physical light passing through thick glass panels.
- Dark-Lock Authentication Architecture: High-specificity stylesheet rules and inline head scripts 
  guarantee that Login and Register portals remain in luxury obsidian dark mode regardless of OS theme.
- Lenis Inertia Scrolling: Ultra-smooth, hardware-accelerated momentum scrolling on all administrative tables.
- Framer Motion Spring Physics: Tactile bouncing on button presses, interactive pill navigation tabs, 
  and card hover elevations.
- Interactive Canvas Particle Sparks: Dynamic click-spark particle generator emitting gold and neon 
  particles upon interactive button clicks.
- Responsive Mobile Bottom Sheet Drawer (js/mobile-bottom-sheet.js): Touch gesture-driven bottom drawer 
  allowing full mobile POS operation on tablets and smartphones.

2.7 Role-Based Access Control (RBAC) & Enterprise Security (firestore-rules.txt, js/auth.js)
--------------------------------------------------------------------------------------------
- Role Definitions:
  * Administrator (Admin): Unrestricted access to financial reports, profit calculations, 
    inventory procurement, user invitation, system settings, and Gemini API keys.
  * Sales Associate (Staff): Restricted access strictly isolated to POS billing, personal sales logs, 
    customer contact lookup, and read-only stock level verification.
- Cloud Firestore Security Guards:
  * signedIn(): Enforces Firebase authentication tokens on every database request.
  * isActiveAdmin(): Validates caller UID against the `admins` collection and confirms active status.
  * isActiveStaff(): Validates caller UID against the `staff` collection.
  * stockOnlyUpdate(): Crucial security rule allowing POS staff to modify ONLY `stock`, `status`, 
    and `updatedAt` on product documents, preventing staff from altering retail prices or descriptions.
  * Destructive Operations Guard: Restricts deletion of sales, products, and customer profiles exclusively to Admins.
- Session Security & Inactive Quarantine: Deactivated employees (?inactive=1) are instantly signed out 
  and barred from reading any cached or realtime store data.

3.1 Point of Sale (POS) & Billing Terminal
------------------------------------------

- Stock Safeguard Validation: Real-time validation preventing billing quantities from exceeding available stock.
- Automated Live Price Calculation: Real-time computation of Subtotal, CGST/SGST Taxes, Discounts, and Grand Total.
- Multi-Method Payment Gateways: Supports Cash, Credit/Debit Card, UPI / QR Code, and Store Credit.
- Customer Association: Quick dropdown linking sales to registered customer profiles for loyalty tracking.
- Instant Thermal Receipt Generation: One-click generation of formatted thermal receipts ready for 80mm/58mm POS printers.
- Full Commercial Invoicing: Generates formal A4 business tax invoices with complete shop metadata, tax breakdown, and signatures.
- Transaction Origin Tagging: Every sale records the originating cashier UID and role (admin vs staff) for shift auditing.

3.2 Product Catalog & Inventory Governance
------------------------------------------
- Comprehensive Product Metadata: Tracks Name, Category, SKU/Barcode, Cost Price, Selling Price (MRP), 
  Current Stock, Minimum Reorder Threshold, and Supplier Association.
- Automated Tri-State Stock Badges: Dynamically computes status:
  * "Available" (Stock > Reorder Level) - Emerald Neon Badge
  * "Low Stock" (Stock <= Reorder Level and Stock > 0) - Amber Alert Badge
  * "Out of Stock" (Stock <= 0) - Crimson Alert Badge
- AI Spreadsheet Import: Drag-and-drop Excel (.xlsx, .xls) and CSV import powered by Gemini multi-model 
  column mapping and synonym auto-detection.
- Batch Management: Supports multi-batch stock tracking (`productBatches`) for expiring or multi-vendor goods.
- Manual Stock Adjustment Modal: Allows warehouse managers to perform rapid stock audits and inventory reconciliations.
- Fast vs Slow Moving Product Ranking: Real-time sales velocity algorithm categorizing products into fast-turnover 
  cash cows and slow-moving dead stock.

3.3 Supply Chain & Purchase Restock Management
----------------------------------------------
- Vendor & Supplier Profiles: Records Vendor Name, Contact Person, Phone, Email, Physical Address, and Supplied Categories.
- Purchase Order Requisitions: Formal restock intake recording Supplier ID, Product ID, Inward Units, Unit Purchase Rate, 
  Total Purchase Cost, Invoice Date, and Payment Status.
- Automated Inventory Increment: Approving a purchase order instantly increases warehouse stock levels in Cloud Firestore.
- Purchase History Ledger: Complete historical audit trail of all inventory inward movements, vendor invoices, and cost trends.
- Supplier Relationship Tracking: Links vendor performance to product quality, lead times, and fulfillment history.

3.4 Customer Relationship Management (CRM) & Directory
------------------------------------------------------
- Customer Profiles: Maintains Customer Name, Phone Number, Email, Billing Address, and Date Joined.
- Automated Lifetime Value (LTV) Calculation: Dynamically aggregates total historical purchases, visits count,

- Unified Contact Directory: Hybrid directory view synthesizing both retail buyers and wholesale suppliers 
  into a single high-efficiency search index.
- Quick Communication Triggers: One-click actions to initiate direct phone calls or launch pre-filled email client drafts.

3.5 Predictive Analytics & Demand Forecasting
---------------------------------------------
- Historical Velocity Analysis: Calculates Average Daily Sales (ADS) over 30-day, 60-day, and 90-day moving windows.
- Stockout Runway Countdown: Real-time calculation estimating the exact number of days remaining before an item reaches zero units:
  Formula: Stock Finish Days = Current Stock Level / Average Daily Sales
- Intelligent Reorder Recommendations: Computes recommended economic reorder quantities:
  Formula: Suggested Reorder = Average Daily Sales * 30 Days Buffer + Safety Threshold
- Future Demand Trajectory Charting: Chart.js visualization plotting past sales against projected future demand curves.
- Forecasting Persistence: Ability to save and track generated forecasts in the Firestore `forecasting` collection for historical verification.

5. DATA MODEL & CLOUD FIRESTORE SCHEMA REFERENCE
================================================================================

5.1 Primary Cloud Firestore Collections
---------------------------------------
1. `admins`
   - Document ID: Firebase Auth UID
   - Fields: name (string), email (string), role ("Admin"), status ("active" | "inactive"), 
     photoURL (string), createdAt (timestamp), lastLoginAt (timestamp).

2. `staff`
   - Document ID: Firebase Auth UID
   - Fields: name (string), email (string), role ("Sales Staff"), status ("active" | "inactive"), 
     photoURL (string), createdAt (timestamp), lastLoginAt (timestamp), invitedBy (admin UID).

3. `products`
   - Document ID: Auto-generated Firestore ID
   - Fields: name (string), category (string), sku (string), barcode (string), price (number), 
     costPrice (number), stock (number), minStock (number), supplierId (string), supplierName (string), 
     status ("Available" | "Low Stock" | "Out of Stock"), source ("real" | "demo"), isDemo (boolean), 
     createdAt (timestamp), updatedAt (timestamp).

4. `productBatches`
   - Document ID: Auto-generated Firestore ID
   - Fields: productId (string), batchNumber (string), expiryDate (timestamp), quantity (number), costPrice (number).

5. `sales`
   - Document ID: Auto-generated Firestore ID
   - Fields: invoiceNo (string), items (array of {productId, name, price, qty, total}), subtotal (number), 
     discount (number), tax (number), total (number), paymentMethod ("Cash" | "Card" | "UPI" | "Credit"), 
     customerId (string), customerName (string), staffId (string), staffName (string), role ("admin" | "staff"), 
     source ("admin" | "staff" | "dummy"), isDemo (boolean), createdAt (timestamp), date (string YYYY-MM-DD).

6. `customers`
   - Document ID: Auto-generated Firestore ID
   - Fields: name (string), email (string), phone (string), address (string), totalOrders (number), 
     totalSpend (number), createdAt (timestamp), updatedAt (timestamp).

7. `suppliers`
   - Document ID: Auto-generated Firestore ID
   - Fields: name (string), contactPerson (string), email (string), phone (string), address (string), 
     categories (array of string), createdAt (timestamp).

8. `purchases`
   - Document ID: Auto-generated Firestore ID
   - Fields: supplierId (string), supplierName (string), productId (string), productName (string), 
     quantity (number), unitCost (number), totalCost (number), invoiceNo (string), purchaseDate (string), 
     createdAt (timestamp).

9. `notifications`
   - Document ID: Auto-generated Firestore ID
   - Fields: title (string), message (string), type ("stock" | "sale" | "restock" | "system"), 
     read (boolean), targetRole ("all" | "admin" | "staff"), createdAt (timestamp).

10. `forecasting`
    - Document ID: Auto-generated Firestore ID
    - Fields: productId (string), productName (string), currentStock (number), ads (number), 
      stockFinishDays (number), suggestedReorder (number), generatedAt (timestamp).

11. `businessSettings`
    - Document ID: "main" (Singleton configuration)
    - Fields: storeName (string), email (string), phone (string), address (string), currencyCode (string), 
      currencySymbol (string), taxRate (number), defaultMinStock (number), updatedAt (timestamp).
